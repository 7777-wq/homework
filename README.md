Step 1: Identify at least 3 problems
Informal word: "super easy" — Too casual for a technical README (GitHub documentation). 
Vague wording: "intro file" / "do the necessary editing" / "ask somebody" — Not specific; readers don’t know what file, what edits, or who to ask. 
Unclear instruction: "Save it with Publish" — Ambiguous. On GitHub, Publish is an action/button, not a way to "save". 
Choppy, repetitive short sentences — The lines are fragmented; flow is poor for instructions. 
"Check it afterwards" is vague — It does not say what to check (preview, rendered markdown).
Step 2: Rewrite (clear, formal, suitable for GitHub README)
Updating your README introduction is straightforward.
Open the file and make your required changes. 
Commit your edits and click Publish to save. 
Preview the rendered README to verify your updates. 
Contact a team member if you lack editing permission.
